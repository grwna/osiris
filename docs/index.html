Osiris API Reference

Release signing, verification, trust management & signed SBOM

Programmatic interface documentation for the Osiris Go packages.

  • Version: 0.1.0
  • Language: Go
  • Source: github.com/grwna/osiris
  • Course: IF4020 Cryptography

Osiris implements deterministic software release signing and verification using standard library Go cryptography. The core verification lifecycle separates hashing, manifest binding, cryptographic signing, and trust evaluation.

Canonical Manifest Format

Signatures are calculated over canonical manifest bytes (schema minisign-manifest/v1). The manifest binds package name, version, signing profile, public key fingerprint (KeyID), and artifact SHA-256 into a sorted JSON structure without extraneous whitespace: 

{"schema":"minisign-manifest/v1","package":"contoh-app","version":"1.0.0","algorithm":"ed25519","keyid":"ac18e2e7f6b47fb4473b6b9d9df671587602a2f448fdb2b951809a7d7521324a","artifact":{"name":"app.zip","size":7240,"sha256":"4d82f7c001ec4cf32646d616d6ee477ea002a2818a7c645ec266ef61014e305e"}}

During verification, the parsed manifest is re-encoded using the identical canonical encoder and compared byte-for-byte against the original manifest payload. Any reordering of keys or whitespace differences causes verification to reject the manifest with FORMAT_ERROR.

Usage Example

privPEM, pubPEM, keyid, err := crypto.GenerateKey(crypto.Ed25519)
if err != nil {
    log.Fatal(err)
}

prof, signer, err := crypto.ParsePrivateKeyPEM(privPEM)
if err != nil {
    log.Fatal(err)
}

_, pubKey, pubKeyID, err := crypto.ParsePublicKeyPEM(pubPEM)
if err != nil || pubKeyID != keyid {
    log.Fatal("public key mismatch")
}

msg := []byte("payload to sign")
sig, err := crypto.Sign(prof, signer, msg)
if err != nil {
    log.Fatal(err)
}

if !crypto.Verify(prof, pubKey, msg, sig) {
    log.Fatal("verification failed")
}

if err != nil {
    log.Fatal(err)

    log.Fatal(err)

    log.Fatal("package not allowed")
}

OK0Release verified successfully.Valid signature, matching hash, authorized key.
INPUT_ERROR2Missing files, bad paths, or invalid CLI parameters.Artifact path does not exist.
FORMAT_ERROR1Schema invalid, duplicate JSON keys, or corrupted trust store.Manifest contains duplicate keys or non-canonical formatting.
UNSUPPORTED_ALGORITHM1Manifest algorithm is not one of the 3 locked profiles.Manifest specifies algorithm "ed448".
KEY_NOT_TRUSTED1KeyID missing from trust store or package unauthorized.Key entry does not allow specified package.
INVALID_SIGNATURE1Signature does not verify over manifest bytes.Signature bit flipped or manifest version altered.

Security Notes

  • Memory clearing: Private key DER bytes parsed from PKCS#8 PEM blocks are wiped from memory via clear(der) immediately after decoding.
  • Strict size limits: Input buffers are capped (manifest: 16 KiB, bundle: 64 KiB, trust store: 1 MiB, SBOM: 16 MiB) to prevent memory exhaustion attacks.
  • Canonical serialization: Manifests are serialized with sorted JSON keys and no extra whitespace. Verification checks canonical equality byte-for-byte.
  • No auto-trust: The verification command is read-only and never modifies the trust store. Public keys must be explicitly added via osiris trust add.
